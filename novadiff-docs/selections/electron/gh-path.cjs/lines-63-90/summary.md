### What it does`resolveViaLoginShell` attempts to locate the `gh` executable by invoking a login shell and asking it to resolve the command path. It returns the absolute path to `gh` if found, or `null` if it cannot determine the location or if the platform is Windows.### How it works1. **Platform guard** – If `process.platform === "win32"`, the function immediately returns `null` because the login‑shell strategy is not applicable on Windows.2. **Shell candidates** – It defines an array `shells` containing two tuples: `["/bin/zsh", ["-ilc", "command -v gh"]]` and `["/bin/bash", ["-lc", "command -v gh"]]`.3. **Iterate over shells** – For each `[shell, args]` pair: * Skip the shell if `fssync.existsSync(shell)` is `false`. * Run the shell with `spawnSync`, passing `args`, `env`, `encoding: "utf8"`, and a `timeout` of8000ms. * Capture the first line of `stdout`, trim it, and store it in `found`. * If `found` is non‑empty and `fssync.existsSync(found)` is `true`, return `found`.4. **Fallback** – If none of the shells yield a valid path, the function returns `null`.### Notes for reviewers- The function relies on `spawnSync`’s synchronous behavior; any error during execution is silently ignored (`catch {}`), so the next shell is tried.- The timeout of8000ms may be too short for very slow shells; consider making it configurable.- The function only checks `/bin/zsh` and `/bin/bash`; other shells (e.g., `fish`, `tcsh`) are not considered.- The returned path is verified with `fssync.existsSync`, ensuring the file actually exists before returning it.
